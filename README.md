# 《吉星派对》随机挑战

随机抽取角色、地图与不重复的四人队伍。保留原来的四条命令，增加图鉴自动同步、管理员手动同步与数据状态查询。

## 使用

| 命令 | 作用 |
| --- | --- |
| `/星趴角色` | 抽取一名已上线角色，显示称号和姓名 |
| `/星趴队伍` | 抽取四名不同角色 |
| `/星趴地图` | 抽取常驻合作地图（默认） |
| `/星趴地图 对战` | 抽取常驻标准对战地图 |
| `/星趴地图 限时` | 抽取限时地图存档，结果会提醒确认是否开放 |
| `/星趴地图 全部` | 包括合作、对战、限时存档 |
| `/星趴随机 [合作/对战/限时/全部]` | 地图与四人队伍一起抽取 |
| `/星趴数据` | 查看来源、数据时间与数量 |
| `/星趴更新` | 仅 AstrBot 管理员：立即同步图鉴 |
| `/星趴帮助` | 查看命令 |

指令前缀遵循 AstrBot 设置。无参数时仍默认抽合作地图。联动角色可能已无法获取，但已持有者仍可使用，因此保留在角色池。角色不会重复，地图与角色等概率抽取；不检查玩家是否拥有角色。

## 安装与配置

Python 3.10+、AstrBot 4.x（需要支持 `AstrBotConfig` 和 `StarTools.get_data_dir`）。无新增第三方运行依赖。

本更新版本的安装地址：`https://github.com/shangzhimingge/astrbot_plugin_astralparty`。在插件管理中通过 Git 链接安装；升级现有安装前先备份原目录，避免同时安装两个同名插件。原项目：[Aurora4123/astrbot_plugin_astralparty](https://github.com/Aurora4123/astrbot_plugin_astralparty)。

将整个插件目录放入 AstrBot 的 `data/plugins/astrbot_plugin_astralparty`，随后重载插件。升级时必须连同 `catalog.py`、`data/catalog.json` 和 `_conf_schema.json` 一起复制。

插件配置面板：
- **自动同步角色与地图图鉴**：默认开启，加载后后台检查，不阻塞抽取。
- **自动同步间隔**：默认 24 小时，可设 1–720 小时。
- **默认地图模式**：默认合作，可选对战或全部；全部包括限时存档。

同步直接读取国内 BWIKI，无需 GitHub Token，不下载或执行远程 Python。每次读取两份图鉴，单次请求超时 15 秒、响应最大 4 MiB。姓名/ID/时间/模式会校验；角色缺失、地图数量减少、网络故障、解析失败或写入失败时保留旧数据。地图分组按图鉴导航表同步，不推断当期匹配轮换或限时活动开放状态。

成功后原子写入 AstrBot 工作目录下的 `data/plugin_data/astrbot_plugin_astralparty/catalog.json`，重启后继续使用。缓存损坏时回退到内置快照。新版本的内置快照若比缓存新，会优先使用内置快照。自动同步失败后按正常间隔重试，也可发送 `/星趴更新`。卸载插件会取消后台任务。

角色按图鉴上线时间（北京时间）过滤；只有图鉴提供了正确时间才会自动解锁。未来角色可能先被收录，但未到上线时间不会进入抽取池。地图暂不自动判断未来上线时间，新增地图需以图鉴常驻/限时分类为准。

## 以后怎样更新

正常情况无需改代码：等待定时同步，或发送 `/星趴更新`。

维护者更新随插件发布的离线快照：

```bash
python scripts/update_catalog.py
```

提交生成的 `data/catalog.json` 即可，不需要修改 Python 枚举。脚本复用运行时的完整性校验，失败时不覆盖原文件。服务器不能访问 BWIKI 时，可在能访问的电脑运行脚本，然后复制快照。

图鉴尚未更新时，也可以编辑 `data/catalog.json`：
- 角色条目：`id`（唯一字符串）、`name`、`title`、`release_at`（北京时间 `YYYYMMDDHHMM`）。
- 地图条目：`id`（唯一字符串）、`name`、`mode`（`pve` / `pvp` / `limited`）。
- 保持 `schema_version: 1`，将 `synced_at` 改为当前带时区的 ISO 时间。

手工维护后关闭自动同步，并重载插件。若旧缓存时间更新，可备份并移走缓存文件，强制使用内置快照；重新开启自动同步后，数据以图鉴为准。删除角色或地图需手工核查，不会由自动同步静默执行。
